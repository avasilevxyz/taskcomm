# 0165. SQL чтений для разбора

- **Дата:** 2026-11-14
- **Статус:** принято

## Контекст

Над таблицами интерфейса есть команда curl: как повторить запрос REST вне интерфейса. При разборе
инцидента следующий вопрос — какой запрос к базе дал эти строки, чтобы выполнить его в psql,
поменять условие и посмотреть рядом то, чего интерфейс не показывает. Запрос знает только сервер:
его собирают классы чтения из окна, дела, фильтров, курсора и поиска по нагрузке, развёрнутого
по реестру полей. Собрать его копией в браузере нельзя — копия разошлась бы с сервером.

Таблиц с запросом пять: списки задач и коммуникаций (а с ними — группы и подзадачи в карточке
и подзадачи узла дела), попытки задачи, попытки коммуникации, лента дела.

## Решение

- **Запрос собирается тем же кодом, что выполняет чтение.** Сборка отделена от выполнения:
  чтение строит запрос, потом выполняет его; метод для разбора строит тот же запрос и отдаёт.
  Разойтись тексту с выполняемым не из чего.
- **Публичный API** — запись `SqlQuery` в корневом пакете (текст с параметрами `:имя` и их значения)
  и `default`-методы чтения: `TaskInspection.listSql`, `attemptsSql`, `unitCountsSql`;
  `CommunicationInspection.listSql`, `attemptsSql`, `correlationKeysSql`. Контроллеры стоят
  только на публичном API ([0140](0140-rest-controllers.md)), поэтому запрос идёт через него.
  Методы `default` и по умолчанию бросают `UnsupportedOperationException`: чужая реализация
  интерфейса не ломается.
- **Предел — размер страницы.** Чтение берёт строкой больше, чтобы узнать о следующей странице;
  запрос для разбора — ровно страницу. У списков это первая страница либо та, курсор которой
  передан.
- **Значения подставляет REST**, литералами PostgreSQL: строки в одинарных кавычках с удвоенной
  кавычкой, `uuid` и `timestamptz` с приведением, списки для `IN` через запятую, пределы времени —
  `-infinity` и `infinity`, как их передаёт драйвер. Подстановка обходит строки и идентификаторы
  в кавычках и приведения `::`. Стартер этот текст не выполняет: его запросы по-прежнему идут
  с параметрами.
- **Выходы REST** — `…/sql` рядом с каждым чтением, с теми же параметрами:
  `GET /tasks/sql`, `GET /tasks/{level}/{id}/attempts/sql`, `GET /communications/sql`,
  `GET /communications/{id}/attempts/sql`, `GET /executions/{id}/outline/sql`. Ответ —
  `{"sql": "..."}`. У схемы дела — несколько запросов подряд, каждый с заголовком комментарием;
  выключенной подсистемы в нём нет.
- **Значок «SQL»** над таблицами — рядом с «curl» и «Столбцами»; открывает запрос в боковой
  панели с подсветкой и «Копировать». Подсветка — новый пакет **`@codemirror/lang-sql`** (6.10.0,
  диалект PostgreSQL), точной версией, как остальные пакеты CodeMirror.
- **Схема таблиц остаётся внутренней.** Панель и Javadoc `SqlQuery` говорят прямо: запрос — для
  разбора, не для отчётов, и меняется вместе со стартером.

## Рассмотренные варианты

- **Строить SQL в браузере.** Отвергнуто: вторая сборка запроса, которая разойдётся с сервером
  при первой правке; поиск по нагрузке требует реестра полей из базы.
- **Отдавать SQL внутренним бином мимо публичного API.** Отвергнуто: `rest` зависит только
  от `api` ([0087](0087-architecture-rules.md), [0140](0140-rest-controllers.md)).
- **Текст с `:имя` и списком значений.** Отвергнуто: выполнить сразу нельзя, подставлять вручную —
  та самая ошибка, от которой кнопка избавляет. Java API при этом отдаёт именно такую форму —
  подстановка только в REST, для человека.
- **Показывать SQL простым текстом.** Отвергнуто: запрос с подзапросами и десятком условий
  читается заметно хуже без подсветки.

## Последствия

- Поверхность публичного API растёт на одну запись и шесть `default`-методов. Это аддитивно.
- Текст запросов чтения виден любому, у кого есть доступ к REST, — под тем же
  `taskcommRequestMatcher`. Выполнить его может только тот, у кого есть доступ к базе.
- Кто-то всё равно построит отчёт на скопированном запросе; правка схемы его сломает, хотя
  контракта не было. Предупреждение в панели это смягчает, но не исключает.
- Окно по умолчанию превращается в конкретные даты на момент запроса.
- Интеграционные тесты выполняют подставленный SQL в PostgreSQL и сверяют строки с чтением:
  разойтись подстановке с выполнением тоже не из чего.
- В зависимостях фронтенда — `@codemirror/lang-sql`; статика в jar интерфейса растёт.
  Потребителю стартера это не приезжает.
