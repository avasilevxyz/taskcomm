# 0148. Памятка для ИИ-агентов внутри jar

- **Дата:** 2026-11-10
- **Статус:** принято

## Контекст

Код с taskcomm у потребителей всё чаще пишет ИИ-агент. Проверили на чистом приложении Spring Boot:
одна сессия агента подключала taskcomm по ссылке на GitHub, другая — уже без ссылки — добавляла
процессор исходящей коммуникации.

- Подключение прошло по README и быстрому старту, но в инструкции проекта агент ничего о taskcomm
  не записал.
- Вторая сессия руководство не открывала ни разу и не знала, что оно есть. С исходниками на диске
  она читала Javadoc; без них — `unzip -l` по jar из кэша Gradle и `javap -c`, в том числе
  по классам `internal`, откуда брала умолчания.
- Процессор в обоих случаях заработал, но агент не предупредил, что имя системы и поля запроса
  стали форматом данных, интеграционного теста не написал, а за собой чистил таблицы `tc_*`
  прямым `DELETE`.

Агент начинает с артефакта, а не с репозитория. Правил, которых нет в сигнатурах, в артефакте
не было, а ссылки Javadoc на руководство — относительные пути, по которым из jar не перейти.

## Рассмотренные варианты

### A. Памятка в jar, страница руководства как источник — выбрано

`docs/guide/agents.md` при сборке кладётся в `taskcomm-autoconfigure.jar` как
`META-INF/taskcomm/AGENTS.md`, относительные ссылки переписываются в абсолютные на тег версии.
Её видит любой агент, который заглянул в jar, — как это и делали обе сессии, — и она совпадает
с подключённой версией. Текст один: в репозитории это обычная страница руководства.

### B. Skill или плагин для Claude Code — отложено

Подхватывается сам, без поиска по jar, но доходит только до тех, кто его поставил, и только
до одного агента. Строится из той же памятки, если понадобится.

### C. `llms.txt` в корне репозитория — отвергнуто сейчас

Помогает агенту, которому дали ссылку на GitHub, а с подключением по ссылке агент и так
справился. Проблема — во второй сессии, где ссылки нет.

### D. Памятка из одних ссылок, без пересказа правил — отвергнуто

Не нарушает «каждый факт в одном месте», но каждое правило агент получает, только сходив
по ссылке в сеть. В эксперименте агент брал ровно то, что видел у себя на диске.

### E. Перевести все пути `docs/...` в Javadoc на абсолютные ссылки — отвергнуто

Ссылок около трёхсот, почти все — на ADR, и при каждом выпуске их пришлось бы переписывать.
Хватает одного правила в Javadoc корневого пакета и абсолютных ссылок там, где ошибка стоит
данных.

## Решение

- **Источник — страница [docs/guide/agents.md](../guide/agents.md)**: где что читать и правила,
  которых не видно из кода. Правила в ней — **короткая выжимка с повтором**, а не одни ссылки:
  агент видит их сразу в jar, без похода в сеть. Это сознательное исключение из «каждый факт
  в одном месте». Каждое правило ссылается на свою страницу, и при расхождении верна страница.
  Одно правило живёт только в памятке: таблицы `tc_*` потребитель не читает и не меняет напрямую.
- **`processResources` модуля `taskcomm-autoconfigure`** кладёт её в jar как
  `META-INF/taskcomm/AGENTS.md` и переписывает относительные ссылки на
  `https://github.com/avasilevxyz/taskcomm/blob/v<версия>/docs/guide/...`.
- **Javadoc корневого пакета** говорит, от чего считаются пути `docs/...`, где граница публичного
  API и где памятка. **`TaskProcessor` и `CommunicationProcessor`** называют формат данных — имя,
  поля нагрузки, транспорт — прямо и ссылаются на Совместимость абсолютной ссылкой.
- **Задача `verifyVersionedLinks`** в составе `check` валит сборку, если в исходниках есть ссылка
  на тег не текущей версии.
- **Быстрый старт** просит записать taskcomm в инструкции проекта.

## Последствия

- Памятка попадает к потребителю только с выпуском: в 2.0.0 её нет.
- Поднял версию — переписываешь ссылки на тег в Javadoc; `verifyVersionedLinks` не даст забыть.
- Новое правило для агента, которое следует из кода, а не из его сигнатур, добавляется в памятку.
- **Правило в памятке может отстать от своей страницы.** Меняешь правило руководства, которое
  в ней пересказано, — правишь и памятку; сборка этого не проверит.
- Ссылки памятки ведут только внутрь руководства: `../` переписывание не разбирает.
- Эксперимент воспроизводим: тот же проект и те же две фразы покажут, помогла ли памятка.
