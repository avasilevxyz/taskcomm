# 0140. Контроллеры REST: зависимости, пути, создание из JSON, дело целиком

- **Дата:** 2026-11-05
- **Статус:** принято

## Контекст

Этап 6c ставит контроллеры поверх API чтения [0138](0138-inspection-api.md) и управления
[0139](0139-restart-api.md). Состав задан [0014](0014-rest-api.md), выключенность по умолчанию —
[0091](0091-rest-disabled-by-default.md), окно истории — [0101](0101-active-partition-horizon.md),
дело одной выдачей — [0064](0064-entity-origin-links.md). Открытыми оставались зависимости, создание
задач и коммуникаций по сырому JSON, объём выдачи дела и форма маппинга в DTO.

## Рассмотренные варианты

### Зависимости

- **Стартер тянет `spring-boot-starter-webmvc`.** Tomcat и MVC приехали бы каждому потребителю, даже
  без REST, который выключен по умолчанию. Отвергнуто.
- **`spring-webmvc` и `spring-security-web` — `compileOnly`, версии из BOM — выбрано**, как
  `jackson-dataformat-xml` в [0135](0135-communication-engine.md). Автоконфигурация REST стоит под
  `@ConditionalOnWebApplication(SERVLET)` и `@ConditionalOnClass(DispatcherServlet)`; бин
  `taskcommRequestMatcher` — только при Spring Security на classpath. Без Security бина нет, и закрыть
  пути потребитель обязан своими средствами.

### Создание из JSON

- **Передать разобранное дерево как нагрузку.** Тип нагрузки проверился бы только в воркере —
  ошибка клиента стала бы падением задачи через минуту, а не `400`. Отвергнуто.
- **Отложить создание.** Оно в составе 0014. Отвергнуто.
- **Методы «из JSON» в сервисах — выбрано:** `TaskService.submitJson` и
  `CommunicationService.sendJson` разбирают JSON в тип из дженерика процессора до записи;
  не разобралось — `UnreadablePayloadException`, наследник `TaskcommException` в корневом пакете,
  общий для подсистем.

### Дело одной выдачей

- **Предел на вид с признаком усечения** и **только задачи и коммуникации** — отвергнуты.
- **Всё без предела — выбрано.** Выдача читает партицию дела страницами API чтения и отдаёт её
  целиком, в порядке создания, у каждой строки — её создатель; плюс ключи корреляции. Время
  создания дела не задано — дело ищется по идентификатору.

### Маппинг в DTO

Снимки 0138 — интерфейсы с методами вида `id()`, а MapStruct видит свойства только у JavaBean-геттеров
и записей.

- **Фабрики `of()` в DTO** — ручной маппер, исключение из правила проекта. Отвергнуто.
- **Своя стратегия имён MapStruct** — отдельный модуль сборки ради одного пакета. Отвергнуто.
- **MapStruct с `expression` на каждое поле — выбрано.** Правило соблюдено, код генерирует MapStruct.
  Бин маппера — сгенерированный класс напрямую, без `Mappers.getMapper`: MapStruct у стартера
  `compileOnly`, его рантайма у потребителя нет.

### Ошибки и имена параметров

- Обработчики ошибок — в базовом классе контроллеров, а не в `@ControllerAdvice`: совет действовал бы
  на контроллеры потребителя. Необъявленное поле поиска — `400` со списком известных полей; неразбираемая
  нагрузка, чужой курсор, пустое окно, неизвестный тип — `400`; не найдено — `404`; отмена
  и перезапуск отвергнуты — `409`.
- Имена параметров MVC указаны в аннотациях явно: стартер компилируется без `-parameters`.

## Решение

Пути под `taskcomm.rest.base-path`:

- задачи — `GET /tasks` (уровень, тип, статусы, родитель, дело, поля `field.<имя>`, окно, страница),
  `GET /tasks/{level}/{id}` и `/attempts`, `POST /tasks/{level}/{id}/cancel` и `/restart`,
  `POST /tasks?type=` с нагрузкой телом, `GET /tasks/search-fields`, `GET /tasks/summary`,
  `POST /tasks/discard-child-results`;
- коммуникации — `GET /communications` (направление, система, статусы, `requestId`, дело, окно,
  страница), `GET /communications/{id}` и `/attempts`, `POST /communications/{id}/cancel` и `/restart`,
  `POST /communications/outbound/{destination}` с запросом телом, `GET /communications/summary`,
  `GET /communications/circuit-breakers`;
- дело — `GET /executions/{id}`.

Одна сущность ищется в окне либо, если передан `executionCreatedAt`, ровно в партиции своего дела.
Нагрузки и результаты вставляются в ответ сырым JSON. Контроллер подсистемы появляется, только если
включена подсистема.

## Последствия

- В сервисах — два новых метода «из JSON»; в корневом пакете — новое исключение.
- Выдача дела с миллионом подзадач — миллион строк в одном ответе, и это выбор, а не недосмотр.
- Приложение без Spring Security получает открытые пути REST, если включило REST.
- Маппер многословен: каждое поле названо выражением.
