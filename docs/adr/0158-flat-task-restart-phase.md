# 0158. Перезапуск плоской задачи — с обработки

- **Дата:** 2026-11-12
- **Статус:** принято

## Контекст

[0069](0069-parent-phase-column.md) записал: перезапуск группы или задачи — новая попытка раскрытия,
фаза `EXPAND`. Правило писалось про родителей и не учло задачу формы `FLAT`: раскрытия у неё нет,
единственная фаза — обработка. Перезапущенная упавшая плоская задача захватывалась на раскрытие,
воркер не находил у процессора метода этой фазы, и каждая попытка падала с «захвачена по другой
форме контракта», пока не кончались повторы. Ошибка есть в выпущенной 2.1.0.

## Решение

- Перезапуск задачи ставит **первую фазу записанной формы контракта** — ту же, что ставит первый
  захват ([0026](0026-contract-shape-marking.md)): `PROCESS` у `FLAT`, `EXPAND` у `UNIT` и `BATCH`.
  Группа, как и прежде, перезапускается с `EXPAND`.
- Фаза берётся из `contract_shape` строки задачи тем же обновлением, что переводит её в `PENDING`:
  отдельного чтения и знания о текущем процессоре перезапуску не нужно. Если форма с тех пор
  у процессора сменилась, расхождение ловит захват по общим правилам, как у любой задачи.
- Причина в `TaskRestartResult.Accepted` у плоской задачи — «обработка заново», а не «новое
  раскрытие».

## Рассмотренные варианты

- **Брать форму у текущего процессора.** Отвергнуто: перезапуск тогда зависел бы от того, есть ли
  процессор на экземпляре, а смена формы — уже отдельный случай, который ловит захват.
- **Сбрасывать фазу и форму в пустое, как до первого захвата.** Отвергнуто: стёрлось бы, по какой
  форме задачу начали выполнять, и смена контракта прошла бы молча
  ([0026](0026-contract-shape-marking.md)).

## Последствия

- Изменение — исправление поведения, публичный API не меняется.
- Упавшие на 2.1.0 после перезапуска плоские задачи достаточно перезапустить ещё раз на версии
  с исправлением.
