# 0135. Движок коммуникаций: разбор SOAP, захват, исход по ответу, синхронный приём

- **Дата:** 2026-11-05
- **Статус:** принято
- **Изменено:** [0136](0136-communication-dedup-and-callbacks.md) — заглушки «до 5c» сняты: ключи дедупликации и корреляции
  и приём колбэка работают.

## Контекст

Этап 5b реализует коммуникации поверх API 5a ([0134](0134-communication-public-api-shape.md)):
создание с первой попыткой, одноветочный захват, воркер, повторы, обмен в попытке, исход по ответу,
синхронный приём и системы без процессора. Дедупликация, корреляция и асинхронный ответ — этап 5c,
ограничение скорости и размыкатель — 5d. По дороге открылись вопросы, которых прежние решения
не закрывали: что разбирает SOAP по умолчанию, тянет ли стартер XML-библиотеку, что делают методы
API, чья реализация будет только в 5c, и к какому ответу применяются отказные статусы.

## Рассмотренные варианты

### Разбор SOAP по умолчанию

- **Весь конверт в тип `C`** — проще в стартере, но каждый потребитель описывает `Envelope` сам.
  Отвергнуто.
- **Первый элемент `Body` — выбрано.** Конверт SOAP 1.1 и 1.2 снимается разбором JDK, содержимое
  разбирает XML-маппер Jackson. Заголовки SOAP процессор видит в сыром теле записанного запроса.

### XML-библиотека

- **Явная версия в каталоге и `api` в стартере** — каждому потребителю, включая тех, у кого SOAP нет,
  приезжает ещё одна библиотека, а версию при подъёме Boot правят руками. Отвергнуто.
- **Не тащить транзитивно — выбрано.** `jackson-dataformat-xml` у `taskcomm-autoconfigure` —
  `compileOnly` с версией из BOM; SOAP-потребитель подключает её сам.

### Методы API, чья реализация — в 5c

- **Молча игнорировать** — незаписанный ключ дедупликации пропустил бы дубликат без следа. Отвергнуто.
- **Исключение «ещё не реализовано» до записи — выбрано.** Релиза между 5b и 5c не будет.

### Поллеры

- **Только основной поллер и форма `deadline`** — меньше кода сейчас, но свойства `pollers`
  и `claim-order` пришлось бы до 5d отвергать при старте. Отвергнуто.
- **Основной и выделенные поллеры по системам, три формы захвата — выбрано**, своей копией по образцу
  задач.

## Решение

### Разбор тела

- SOAP по умолчанию: корневой элемент обязан быть `Envelope` пространства SOAP 1.1 или 1.2, внутри —
  `Body`; разбирается его первый дочерний элемент. Тело без конверта — неразбираемое. DTD запрещены:
  внешние сущности в чужом XML не разворачиваются.
- SOAP-процессор, который полагается на разбор по умолчанию, без `jackson-dataformat-xml` в classpath —
  **падение при старте** с подсказкой. Процессор, переопределивший методы разбора, XML-маппера
  не требует; `decodeResponse` проверяется, только если колбэк у процессора есть (`A` не `Void`).
- Исключение из разбора — неразбираемое тело; ошибка записи доменной формы в JSON — нет, она
  бросается вызывающему.

### Захват и повторы

- Захват — одноветочный ([0054](0054-communication-attempt-lifecycle.md)): готовая коммуникация
  в `PENDING` соединяется со своей открытой незахваченной попыткой той фазы, что записана на ней,
  и аренда проставляется в существующую строку. Брошенные попытки того же поллера закрываются
  `LEASE_LOST` в той же транзакции такта ([0067](0067-expired-lease-closes-attempt.md)).
- Поллер берёт только свои системы; осиротевшие не захватываются и не закрываются
  ([0105](0105-orphan-communications.md)).
- Форма контракта исходящей пишется при первом захвате; записанная форма, не совпавшая с текущим
  процессором, — коммуникация `CANCELLED` с причиной, её открытая попытка закрывается `SKIPPED`.
- Неуспех — следующая попытка открывается сразу, без аренды; у входящей в неё копируются `request_*`.
  Отметка отмены на коммуникации делает неуспех `CANCELLED`.

### Исход по ответу

- `failure-statuses` применяются к ответу **исходящей**: у входящей `response_*` — ответ отправителю,
  его формирует наш процессор ([0133](0133-synchronous-inbound-reception.md)), и отказным статусом
  внешней системы он не бывает. WARN «вернулся, не записав ответ» — тоже только у исходящей REST и SOAP.
- Исключение перебивает пропуск; пропуск отменяет проверку статуса.
- Время ответа без явного — момент записи по часам базы.

### Синхронный приём

- Попытка открывается при создании под арендой этого экземпляра; продлевает её тот же поток heartbeat
  движка, что и попытки воркеров. Итог вызывающему строится по перечитанной строке.
- Если попытку успел закрыть переподхват, вызывающий получает `Failed` с причиной «аренда потеряна»,
  а коммуникация идёт по общим правилам повторов — так и задумано в 0133.

### Настройки

- Пять уровней, как у задач ([0061](0061-processor-configuration-annotations.md)); ключи фаз в `yaml` —
  `process` и `handle-response`. Приоритет и отказные статусы — только у системы: на фазе `yaml` или
  на методе это падение при старте.
- Умолчания подсистемы — из дерева в configuration.md: аренда `60s` / `20s` / `5m`, повторы
  `5` / `10s` / `2.0` / `1h` / `0.2`.
- `@TaskProcessorSettings` на процессоре коммуникаций и `@CommunicationProcessorSettings`
  на процессоре задач — падение при старте. Чужая аннотация ищется по имени: подсистемы друг от друга
  не зависят ([0066](0066-processor-settings-annotation-names.md)).

### До этапа 5c

Ключи дедупликации и корреляции при создании, `dedupKey` и `registerCorrelationId` контекста,
`receiveResponse` — `UnsupportedOperationException` до записи. `doNotAwaitResponse` ничего не делает:
без ключа корреляции ответа и так не ждут.

## Последствия

- SOAP-потребитель обязан сам подключить `tools.jackson.dataformat:jackson-dataformat-xml`; пишется
  в consumer-contract.md.
- Захват коммуникаций идёт по индексам `(status, …)` без системы: выделенный поллер редкой системы
  просматривает чужие строки. Нагрузочный сценарий 5d это проверит.
- Входящая с отказным `response_status` в своей попытке успешна — проверки нет.
- Между 5b и 5c часть публичного API бросает исключение; релизом это состояние быть не должно.
