# 0164. Блоки нагрузки и тел обмена — CodeMirror только для чтения

- **Дата:** 2026-11-14
- **Статус:** принято

## Контекст

Нагрузки, результаты, колбэки и тела обмена на карточках показывались простым текстом. CodeMirror
стоял только в форме создания ([0152](0152-web-interface-frontend-stack.md)). Тела коммуникаций
бывают не только JSON: SOAP и прочий XML, обычно одной строкой, — и в таком виде их не прочитать.

## Решение

- Блоки на карточках — **CodeMirror 6 в режиме только для чтения**: подсветка, номера строк,
  сворачивание вложенного, поиск по Ctrl+F, выделение и копирование. Цвета те же, что у редактора
  формы. CodeMirror рисует только видимые строки — большое тело карточку не подвешивает.
- Язык — **по содержимому**: разбирается как JSON — JSON с отступами; начинается с `<` — XML;
  иначе текст без подсветки. Для XML — новый пакет **`@codemirror/lang-xml`**, точной версией,
  как остальные пакеты CodeMirror; `@codemirror/language` и `@codemirror/search`, которые уже
  приезжали с `codemirror`, объявлены явно, раз импортируются напрямую.
- **XML одной строкой — с отступами по вложенности**, только для показа. У XML пробелы между
  тегами бывают значимыми, поэтому многострочный XML, неразобравшийся и с текстом вперемешку
  с тегами показывается как есть.
- Модуль блока грузится лениво, вместе с карточкой; пока он грузится, виден тот же текст без
  подсветки.

## Рассмотренные варианты

- **Свой разбор JSON с подсветкой и номерами строк.** Отвергнуто: XML пришлось бы разбирать
  вторым таким же разборщиком; ни сворачивания, ни поиска; все строки рисуются сразу.
- **Показывать XML только как есть.** Отвергнуто: SOAP одной строкой не читается.
- **Отступы для любого XML.** Отвергнуто: меняют пробелы, которые у XML бывают значимыми.

## Последствия

- В зависимостях фронтенда — `@codemirror/lang-xml`; статика в jar растёт на несколько десятков
  килобайт. Потребителю стартера это не приезжает: только jar интерфейса.
- На карточке — несколько редакторов только для чтения, по одному на блок.
