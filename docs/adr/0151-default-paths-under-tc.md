# 0151. Пути по умолчанию под `/tc`: REST — `/tc/api`, интерфейс — `/tc`

- **Дата:** 2026-11-12
- **Статус:** принято

## Контекст

С [0014](0014-rest-api.md) REST живёт под `taskcomm.rest.base-path` с умолчанием `/api/taskcomm`,
и в таком виде вышел в 2.0.0, 2.0.1 и 2.0.2. Интерфейс ([0149](0149-web-interface-module.md)) получал
умолчание `/taskcomm`. Тогда у стартера два несвязанных префикса, и закрывать в конфигурации
безопасности приходится оба.

Умолчание выпущенного свойства — часть контракта. Кто его не переопределял, после смены получит
REST по другому пути. `taskcommRequestMatcher` переезжает вместе с путями, поэтому конфигурация
безопасности, построенная на нём, продолжит работать. Сломаются внешние вызовы: скрипты, клиенты
других сервисов, правила прокси и балансировщика, закладки, написанные под `/api/taskcomm`.

## Рассмотренные варианты

### A. Оставить `/api/taskcomm`, интерфейсу дать `/tc` — отвергнуто

Совместимо, но два несвязанных префикса остаются навсегда, а «всё под `/tc`» — только для тех, кто
прочитал руководство и переопределил свойство.

### B. Сменить умолчание в следующей мажорной версии — отвергнуто

Правильно по semver, но откладывает общий префикс до выпуска, ради которого больше ничего ломать
не нужно, и интерфейс до тех пор выходит со старым путём REST.

### C. Сменить умолчание сейчас, без мажорной версии — выбрано

Решение человека, закрывшего развилку: стартер выпущен недавно, интерфейса ещё нет ни у кого,
и выгода от одного префикса перевешивает. Цена записана ниже.

## Решение

- **`taskcomm.rest.base-path` по умолчанию `/tc/api`.**
- **`taskcomm.ui.base-path` по умолчанию `/tc`** — изменяет [0149](0149-web-interface-module.md).
  Интерфейс и REST — под одним префиксом, и одно правило `/tc/**` в конфигурации безопасности
  закрывает оба.
- Мажорная версия не поднимается. Это **сознательное отступление** от правила «мажорная — при потере
  обратной совместимости» из CLAUDE.md, единичное: прецедентом для других умолчаний оно не служит.
- Страница обновления версии говорит крупно: кому нужен прежний путь — `taskcomm.rest.base-path:
  /api/taskcomm`, одной строкой.
- REST лежит внутри пути интерфейса, и раздача интерфейса в 11b обязана не перехватывать пути REST:
  неизвестный путь под `/tc/api` — `404` от REST, а не `index.html`.

## Последствия

- У потребителя, полагавшегося на умолчание, REST после обновления отвечает по `/tc/api`, а по
  `/api/taskcomm` — `404`. Номер версии об этом не предупредит, только страница обновления.
- Конфигурация безопасности через `taskcommRequestMatcher` продолжает работать без правок; правила,
  написанные по строке пути, — нет.
- Раздача интерфейса усложняется исключением для путей REST под своим префиксом.
