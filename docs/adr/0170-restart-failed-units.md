# 0170. Перезапуск всех упавших подзадач родителя

- **Дата:** 2026-11-17
- **Статус:** принято

## Контекст

Перезапуск списком ([0169](0169-restart-many.md)) закрывает гонку со сборкой, но ограничен
500 сущностями за вызов и требует выбрать каждую. Самый частый случай другой: внешняя система
лежала, у задачи упали сотни или тысячи подзадач, и их нужно прогнать заново. Выбирать их
по одной бессмысленно, а несколько вызовов по 500 возвращают гонку: между вызовами родитель
успевает уйти в сборку.

## Рассмотренные варианты

- **Интерфейс отбирает упавшие и шлёт их списками по 500.** Гонка между списками остаётся,
  а отбор — чтение всех подзадач родителя в браузер. Отвергнуто.
- **Перезапуск по одному через общий механизм списка — точка сохранения на каждую подзадачу.**
  Тысячи блокировок по одной и тысячи переводов одних и тех же предков. Отвергнуто.
- **Каждая группа отдельно: упавшие группы, где предки не принимают перезапуск, пропускаются.**
  Частичный исход по группам человеку трудно прочесть, а задача всё равно соберётся раньше, если
  часть групп ушла. Отвергнуто.
- **Одна транзакция, всё или ничего, отбор и перезапуск запросами — выбрано.**

## Решение

- `TaskService.restartFailedUnits(TaskSnapshot parent)` → `TaskRestartResult`; `default`
  с `UnsupportedOperationException`. REST — `POST /tasks/{level}/{id}/restart-failed-units`, ответ как
  у перезапуска одной сущности.
- **Какие подзадачи**: `FAILED` без отметки отмены, принадлежащие **последней попытке раскрытия**
  своего родителя, а если родитель — группа, то и группа принадлежит последнему раскрытию задачи.
  У задачи — и подзадачи её групп. Подзадачи прежних раскрытий — история
  ([0098](0098-restart-only-latest-expansion.md)), их не трогаем.
- **Одна транзакция, без предела по числу.** Отбор — одним запросом `FOR UPDATE` по идентификаторам;
  затем блокируются предки — группы, потом задача; затем каждый родитель подзадач переводится в
  ожидание детей тем же условным обновлением, что при перезапуске одной сущности; затем подзадачи
  встают в очередь одним обновлением.
- **Всё или ничего.** Не перевёлся хоть один предок — сборка, отмена, удалённые результаты, новое
  раскрытие ещё не прошло, — откат, и причина называет этого предка. Упавших нет — отказ.
- **Интерфейс**: кнопка «Перезапустить упавшие подзадачи» в карточке задачи и группы с подзадачами;
  исход — с числом перезапущенных.

## Последствия

- Транзакция держит блокировки всех упавших подзадач родителя: на десятках тысяч это заметное время,
  воркеры этих подзадач ждут. Ручная операция, и подзадачи упавшие — их никто не захватывает.
- Отбор идёт коррелированным подзапросом «последняя попытка раскрытия» на каждую упавшую подзадачу —
  по индексу попыток. Это чтение одного дела, не горячий путь.
- Публичный API растёт на один `default`-метод; аддитивно.
