# 0160. Структура нагрузки для формы создания

- **Дата:** 2026-11-13
- **Статус:** принято

## Контекст

Форма создания ([0149](0149-web-interface-module.md), [0153](0153-ui-creation-refinements.md))
принимает нагрузку JSON-редактором и проверяет только синтаксис. Какие ключи ждёт процессор,
человек узнаёт из кода или из `400` после отправки. Стартер при этом класс нагрузки знает: он
выводит его из параметров типа процессора и им разбирает `submitJson` и `sendJson`
([0012](0012-payload-storage.md)).

## Решение

- **Структура строится из класса нагрузки** обходом `acceptJsonFormatVisitor` того же маппера,
  которым нагрузка разбирается, — с `@TaskcommPayloadMapper`, если он задан. Поэтому учитываются
  стратегия имён, `@JsonProperty`, `@JsonIgnore`. Новой зависимости нет: обход — часть
  jackson-databind.
- **Публичный тип `PayloadShape` — в корневом пакете**: вид значения (`STRING`, `INTEGER`, `NUMBER`,
  `BOOLEAN`, `OBJECT`, `MAP`, `ARRAY`, `ANY`), ключи объекта в порядке сериализации, элемент массива
  или значение отображения, допустимые значения перечисления. Тип общий для подсистем и связи между
  ними не создаёт — как `UnreadablePayloadException`.
- **Обход — свой в каждой подсистеме**, в корне её `internal`, рядом с кодеком: общего внутреннего
  пакета у подсистем нет, а расширять исключение [0114](0114-uuidv7-generator-in-execution-internal.md)
  ради него незачем.
- Что маппер не может описать заранее — `Object`, `JsonNode`, свой сериализатор без описания,
  тип, повторившийся выше по пути, путь глубже предела, — `ANY`.
- **Чтение**: `TaskInspection.payloadShape(taskType)` — параметры задачи `TTaskPayload`,
  `CommunicationInspection.requestShape(system)` — запрос `TRequest`. Пусто, если процессора нет.
  В REST — `GET /tasks/payload-shape?type=` и `GET /communications/request-shape?system=`, `404`
  без процессора; пустые части в ответ не попадают.
- **Интерфейс**: при выборе типа или системы в пустой редактор встаёт шаблон — все ключи,
  значения-заглушки по виду: `""`, `0`, `false`, `[]`, `{}`, у `ANY` — `null`. Шаблон заменяет
  только пустое место или прежний нетронутый шаблон: начатую нагрузку и черновик не трогает.
  Редактор проверяет текст по структуре на лету: неизвестный ключ, не тот вид значения, дробь
  в целом, значение не из перечисления, недостающие ключи. Всё это — предупреждения: `null`
  подходит любому виду, обязательность полей маппер не знает, а последнее слово — за разбором
  при создании. Для тела входящей не в JSON шаблона и проверки нет.

## Рассмотренные варианты

- **Пример нагрузки от процессора** — метод `examplePayload()`. Точнее и с осмысленными
  значениями, но пишет его потребитель, и у не написавших шаблона нет.
- **Шаблон из последней задачи типа в истории.** Без изменения API, но у нового типа шаблона нет,
  а устаревшая форма выдаётся за правильную.
- **Пробный разбор на сервере** вместо проверки на клиенте. Точнее — срабатывают свои
  десериализаторы, — но это запрос на каждую паузу в наборе и `POST`, закрытый у читателей
  без права создавать.
- **Обход в публичном API** (`PayloadShape.describe(JsonMapper, Type)`) — одна копия кода, но
  публичный метод с обязательствами совместимости и Jackson в сигнатуре.
- **Свой тип структуры в каждой подсистеме.** Корень не трогается, но два одинаковых публичных
  типа.
- **Заглушки `null` во всех значениях.** Видно, что не заполнено, но шаблон сразу не проходит
  проверку видов.

## Последствия

- Изменение аддитивное: новый публичный тип, по методу в двух интерфейсах чтения, две выдачи REST.
- Корневой пакет хранит не только исключения — общие типы, не связывающие подсистемы.
- Структура — подсказка: свой десериализатор или полиморфизм она не видит, и в таких местах
  шаблон пишет `null`, а проверка молчит.
