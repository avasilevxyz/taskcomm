# Обновление версии

- **Миграции только добавляют.** При поэкземплярном обновлении новая схема какое-то время
  работает со старым кодом, и это безопасно. Удаление колонки — не раньше следующего выпуска после
  того, как код перестал ею пользоваться.
- **Порядок**: сначала миграции, потом новый код. Старый код на новой схеме работает, новый
  на старой — не запустится.
- **Выпущенный файл схемы не меняется никогда** — иначе у всех, кто его применил, сломалась бы
  контрольная сумма Liquibase.
- Миграция, требующая ручного вмешательства, — только с мажорной версией.

## Изменения по версиям

### После 2.0.2: REST переехал на `/tc/api`

Путь REST по умолчанию сменился с `/api/taskcomm` на **`/tc/api`**, мажорная версия при этом
не поднималась ([ADR 0151](../../adr/0151-default-paths-under-tc.md)). Если вы не задавали
`taskcomm.rest.base-path` сами, после обновления REST отвечает по новому пути, а по старому — `404`.

- Конфигурация безопасности через `taskcommRequestMatcher` работает без правок: сопоставитель
  переезжает вместе с путями.
- **Правила безопасности, написанные строкой `/api/taskcomm/**`, после обновления не защищают
  ничего**: REST попадает под ваше правило для всех остальных путей, и если оно мягче — например,
  `authenticated()` вместо роли, — права на отмену, перезапуск и чтение обмена расширяются молча.
  До обновления перейдите на `taskcommRequestMatcher` или верните прежний путь (ниже).
- Правила, написанные по строке пути, — скрипты, клиенты других сервисов, прокси, балансировщик, —
  придётся поправить. Либо верните прежний путь одной строкой:

```yaml
taskcomm:
  rest:
    base-path: /api/taskcomm
```
