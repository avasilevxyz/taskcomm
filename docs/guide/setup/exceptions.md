# Исключения

Всё, что стартер бросает сам, наследуется от `TaskcommException` — непроверяемого исключения
из корневого пакета. Ошибки taskcomm отличаются от прочих одним `catch`. Исключения, брошенные
вашим процессором, стартер не оборачивает: они становятся неуспешной попыткой, см.
[Повторы и ошибки](../tasks/retries.md).

Отдельно стоит `IllegalArgumentException`: её бросают проверки аргументов в публичных типах —
опциях, окне, странице, контексте обработки.

## При старте

| Исключение                       | Когда                                                                                           |
|----------------------------------|-------------------------------------------------------------------------------------------------|
| `TaskcommConfigurationException` | Неверные настройки, тип или система в двух процессорах, расхождение схемы, нет партиции и т. п. |

Приложение не запускается, а сообщение называет, что исправить. Полный перечень проверок —
в [Настройках](configuration.md#проверки-при-старте).

## При создании

| Исключение                   | Когда                                                                                                                   |
|------------------------------|-------------------------------------------------------------------------------------------------------------------------|
| `TaskcommException`          | Тип задачи или внешняя система не объявлены ни одним процессором; класс процессора не зарегистрирован бином             |
| `TaskcommException`          | Тип задачи устарел: процессор помечен `@Deprecated`, новые задачи не ставятся                                           |
| `TaskcommException`          | Создание внутри транзакции, которая не держит `DataSource` taskcomm, — см. [База данных](database.md#база-и-транзакции) |
| `TaskcommException`          | Коммуникация с ключом дедупликации в транзакции с изоляцией выше `READ COMMITTED`                                       |
| `TaskcommException`          | Синхронный приём `receiveAndProcess` вызван внутри активной транзакции                                                  |
| `UnreadablePayloadException` | `submitJson` или `sendJson`: JSON не разбирается в нагрузку процессора. Бросается до записи                             |
| `IllegalArgumentException`   | Приоритет меньше единицы                                                                                                |

Неразбираемое тело входящей — **не исключение**: `receive` возвращает
`ReceiveResult.Unparseable`, а коммуникация сохраняется `FAILED` с сырым телом, см.
[Входящие](../communications/inbound.md).

## При чтении

| Исключение                    | Когда                                                                                   |
|-------------------------------|-----------------------------------------------------------------------------------------|
| `UnknownSearchFieldException` | Поиск по полю, которое не объявил ни один тип. `knownFields()` — список известных полей |
| `TaskcommException`           | Курсор страницы не разбирается — он чужой или собран вручную                            |
| `TaskcommException`           | `result(task, type)`: класс не совпадает с результатом процессора                       |
| `IllegalArgumentException`    | Конец окна `HistoryWindow` не позже начала; размер страницы вне `[1, 1000]`             |

## В процессоре

| Исключение                 | Когда                                                                      |
|----------------------------|----------------------------------------------------------------------------|
| `IllegalArgumentException` | `skip` или `doNotRetry` без причины: причина обязательна и хранится в базе |

## В REST

`TaskcommException` и `IllegalArgumentException` превращаются в `400` с текстом в поле `error`,
`UnknownSearchFieldException` — ещё и со списком `knownFields`. Остальные коды — в
[REST API](../api/rest.md#ошибки).
