# Повторы и ошибки

**Ошибка — это исключение** из метода процессора. Попытка закрывается неуспехом, сущность
возвращается в очередь с паузой, которая растёт экспоненциально и случайно сдвигается
(`jitter`), — иначе тысяча подзадач, упавших из-за недоступности внешней системы, проснулась бы
одновременно и положила её снова. Исчерпала попытки — `FAILED`.

- Повторяется ровно тот уровень, что упал. Упала подзадача — повторится она. Упало раскрытие или
  сборка — повторятся они, под теми же правилами.
- **Лимит попыток у каждой фазы свой**: успешное раскрытие не тратит попыток сборки.
- Неуспешной считается и попытка, у которой истекла аренда (`LEASE_LOST`).

**Неповторяемая ошибка.** Битая нагрузка не станет валидной от повтора. Вызовите
`doNotRetry(reason)` **до** броска исключения — и сущность станет `FAILED` сразу:

```java
if (unit.payload().sku() == null) {
    context.doNotRetry("нет обязательного поля sku");
    throw new IllegalArgumentException("нет обязательного поля sku");
}
```

Без исключения `doNotRetry` ничего не делает, а вызвать его после броска невозможно — порядок
важен, и проверить его за вас нечем.

Параметры повторов — `max-attempts`, `initial-delay`, `multiplier`, `max-delay`, `jitter` —
задаются глобально, на тип задачи, на фазу и аннотацией на процессоре; см. [Настройки процессора аннотациями](settings.md) и
[Настройки](../setup/configuration.md).
