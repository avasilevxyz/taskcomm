# Контекст обработки

`ProcessingContext` приходит в каждый метод процессора.

| Метод                | Что делает                                                                        |
|----------------------|-----------------------------------------------------------------------------------|
| `skip(reason)`       | Объявляет исход «делать нечего». Действует при нормальном возврате                |
| `doNotRetry(reason)` | Запрещает повтор. Действует только вместе с исключением                           |
| `shouldStop()`       | Сигнал прекращения: отменили, потеряна аренда или вы сами вызвали `skip`          |
| `executionRef()`     | Ссылка на текущее дело — для создания из другого потока                           |
| `attemptNumber()`    | Номер попытки этой фазы в текущем цикле повторов, с единицы                       |
| `isRetry()`          | Была ли раньше попытка этой фазы — за всю историю, включая до ручного перезапуска |

Все методы отвечают из памяти и в базу не ходят.

**Пропуск.** `skip(reason)` — единственный способ сказать «делать было нечего»: это не успех
и не ошибка, а статус `SKIPPED` с сохранённой причиной.

```java
@Override
public OrderOutcome process(TaskUnit<OrderRef> unit, ProcessingContext context) {
    if (alreadySynced(unit.payload())) {
        context.skip("заказ уже синхронизирован");
        return null;
    }
    ...
}
```

Пропустить можно на любом уровне — подзадачу, раскрытие, сборку. Исключение после `skip`
перебивает пропуск. Пропуск и результат независимы: вызвали `skip` и вернули значение —
оно сохранится. Пропуск в сборке делает родителя `SKIPPED` поверх свода детей: упавшие дети
его уже не превратят в `WARNING`.

**Сигнал прекращения.** Если обработка длинная, спрашивайте `shouldStop()` между шагами и выходите,
когда он поднят. Различать причины не нужно — реакция одна. Учтите, что нормальный возврат
из недоделанной работы запишется успехом; чтобы отмена действительно остановила работу, выходите
исключением.
