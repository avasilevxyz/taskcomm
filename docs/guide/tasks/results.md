# Результаты

Значение, которое вернули `process`, `collect` или `collectBatch`, сохраняется в базе как
результат попытки. Раскрытие результата не возвращает: его результат — дети.

```java
Optional<SyncSummary> summary = taskService.result(task, SyncSummary.class);
```

`result` отдаёт результат **последней** попытки, если та успешна. Пусто — результата нет,
последняя попытка неуспешна или процессор возвращает `Void`.

**Сохраняется только не-`null`.** Правило одно для успеха и для пропуска: вызвали `skip()`
и вернули значение — оно сохранится и придёт в сборку. Результат не нужен вовсе — поставьте `Void`
в параметре типа и возвращайте `null`.

**Результаты детей удаляются после сборки** — они уже сведены в результат родителя, а хранить
миллион ненужных строк дорого. Когда именно — свойство `taskcomm.results.discard`:

| Значение               | Когда удаляются результаты детей            |
|------------------------|---------------------------------------------|
| `after` (по умолчанию) | Через `discard-after` после успешной сборки |
| `immediately`          | Сразу после сборки                          |
| `never`                | Никогда — только вручную                    |

Вручную — `taskService.discardChildResults()` или `discardChildResults(olderThan)`. Вызов только
отмечает родителей, строки удаляет движок в фоне.

Удаление закрывает одну дорогу: **перезапустить отдельную подзадачу собранной группы уже нельзя**,
только группу или задачу целиком — сборке нужны результаты всех подзадач.
