## Процессор и транспорт

Процессор коммуникаций — адаптер к **одной** внешней системе в обоих направлениях: входящие от неё
и исходящие к ней приходят в один `process`, а направление разбирается по типу коммуникации.

```java
@Override
public Ack process(Communication<Order> communication, CommunicationContext context) {
    return switch (communication) {
        case Communication.Outbound<Order> outbound -> send(outbound, context);
        case Communication.Inbound<Order> inbound -> accept(inbound, context);
    };
}
```

Параметры типа `CommunicationProcessor<TRequest, TSyncResponse, TAsyncResponse>`:

- `TRequest` — доменная форма запроса;
- `TSyncResponse` — доменная форма синхронного ответа: у исходящей — что ответила внешняя система, у входящей —
  что ответить отправителю. `Void` — не хранить;
- `TAsyncResponse` — доменная форма асинхронного ответа (колбэка) на исходящую. `Void` — ответа не ждём.

Контракт выбирается по **транспорту** — он определяет, как разбирается тело входящего сообщения:

| Контракт                      | Тело по умолчанию разбирается как                                          |
|-------------------------------|----------------------------------------------------------------------------|
| `RestCommunicationProcessor`  | JSON                                                                       |
| `SoapCommunicationProcessor`  | XML: снимается конверт SOAP 1.1 или 1.2, разбирается первый элемент `Body` |
| `KafkaCommunicationProcessor` | JSON                                                                       |
| `RawCommunicationProcessor`   | никак — `decodeRequest` и `decodeResponse` пишете вы                       |

Разбор переопределяется методами `decodeRequest(body, headers, decoder)` и
`decodeResponse(body, headers, decoder)`; разбор по умолчанию приходит в них аргументом —
им можно воспользоваться после своей подготовки тела. Исключение из метода разбора — тело
не разбирается.

**Что делает стартер, а что вы.** Стартер хранит коммуникацию и её обмен, раздаёт работу,
повторяет, ограничивает скорость, размыкает. Ходить во внешнюю систему, слушать её и отвечать
ей — ваш код: HTTP-клиент, слушатель Kafka, контроллер. Своего приёмного endpoint и своего
HTTP-клиента у стартера нет.

**SOAP по умолчанию требует `jackson-dataformat-xml`.** Стартер её не тянет. Нет её
в приложении, а SOAP-процессор полагается на разбор по умолчанию, — приложение не запустится
с подсказкой.
