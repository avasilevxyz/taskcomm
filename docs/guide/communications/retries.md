# Повторы и отказные ответы

У коммуникаций **нормальный возврат — ещё не успех.** Если процессор записал ответ с отказным
статусом, попытка становится `FAILED` и уходит в повтор, хотя исключения не было; причину
(«ответ 503») стартер пишет сам.

| Транспорт  | Отказные статусы по умолчанию        |
|------------|--------------------------------------|
| REST, SOAP | `5xx`, `429`                         |
| RAW        | нет — смысл статуса знаете только вы |
| Kafka      | статуса нет                          |

Список задаётся для системы — `failure-statuses` в `yaml` или `failureStatuses` в аннотации;
пустой список выключает правило. Применяется только к ответу **исходящей**: у входящей ответ —
наш собственный.

Остальное — как у задач: исключение — неуспешная попытка, пауза растёт экспоненциально
со случайным сдвигом, `context.doNotRetry(reason)` перед броском запрещает повтор. У фазы
отправки и фазы обработки ответа лимит попыток свой.
