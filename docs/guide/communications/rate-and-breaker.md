# Скорость и размыкатель

## Ограничение скорости

```yaml
taskcomm:
  communication:
    systems:
      supplier:
        rate-limit-per-instance: 10    # отправок в секунду; дробное — реже раза в секунду
```

Лимит считает вызовы отправки исходящих и действует **на экземпляр**: три экземпляра с лимитом 10
дадут внешней системе до 30. Воркер ждёт разрешения перед `process`. Входящие и обработка
колбэков не ограничиваются.

## Размыкатель

Размыкатель (circuit breaker) перестаёт отправлять в систему, которая отвечает отказами. Есть
только у **исходящих**, **выключен по умолчанию**:

```yaml
taskcomm:
  communication:
    systems:
      supplier:
        circuit-breaker: { enabled: true, exceptions: [java.io.IOException] }
```

- **Что считается отказом**: исключение из списка (пустой — любое) и отказной статус ответа.
  Не считаются исключение после `doNotRetry`, превышение предела обработки и истечение ожидания
  колбэка.
- **Когда размыкается**: доля отказов за окно `window` выше `failure-rate-threshold` при числе
  вызовов не меньше `minimum-calls`.
- **Что происходит**: коммуникации системы просто не захватываются — ждут в очереди, попытки
  не сгорают. Через растущий интервал `wait` стартер пробует отправить `probe.calls` коммуникаций;
  все успешны — размыкатель замыкается, иначе ждёт дольше.

Что нужно знать:

- **состояние у каждого экземпляра своё** — три экземпляра размыкаются каждый сам;
- **после замыкания накопленная очередь идёт волной**, её сдерживает только ограничение скорости;
- **от зависания без тайм-аута размыкатель не спасает**: превышение предела он не считает,
  а поток прервать нельзя. Тайм-аут на вашем клиенте — единственная защита.

Каждый переход пишет WARN с системой и долей отказов; состояние видно в метрике
`tc.communication.breaker.state` и в [REST](../api/rest.md).
