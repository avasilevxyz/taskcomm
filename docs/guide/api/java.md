# Чтение из кода

Java API для экранов сопровождения, админок и разбора инцидентов. REST-контроллеры стартера
построены поверх него же, так что всё, что умеет [REST API](rest.md), можно сделать из кода —
например, в своём контроллере со своей безопасностью.

## Что можно прочитать

| Бин                       | Пакет                          | Что даёт                                                                                               |
|---------------------------|--------------------------------|--------------------------------------------------------------------------------------------------------|
| `TaskInspection`          | `task.api.inspection`          | Списки и поиск задач, групп, подзадач; попытки; поля поиска; сводка по типам                           |
| `CommunicationInspection` | `communication.api.inspection` | Списки и поиск коммуникаций; попытки с обменом; ключи корреляции дела; сводка по системам; размыкатели |
| `ExecutionService`        | `execution.api`                | Дело по идентификатору                                                                                 |

Бины появляются вместе со своей подсистемой и внедряются как обычно.

Снимки отдают **сырой JSON нагрузки**, а не доменный объект: сущность осиротевшего типа
восстановить в доменную форму нечем, а показать её нужно. Для доменной формы есть
`TaskService.findInExecution` и `result`.

## Запросы и страницы

Каждое чтение истории принимает **окно** — `HistoryWindow` — и страницу:

```java
Page<TaskSnapshot> page = taskInspection.list(
        TaskQuery.of(TaskSnapshot.Level.UNIT)
                .withType("order-sync")
                .withStatuses(Set.of("FAILED")),
        HistoryWindow.between(from, to),
        PageRequest.first(100));

page.items().forEach(this::show);
page.next().ifPresent(cursor -> loadMore(PageRequest.after(cursor, 100)));
```

**Окно — по времени создания дела**, а не самой сущности: так разложены партиции. Подзадача,
созданная сегодня в деле месячной давности, лежит в партиции того месяца. `HistoryWindow.everywhere()`
снимает окно и обходит все партиции — для разбора, не для экранов, которые открывают часто.
Умолчания у окна в Java API нет: его подставляет только REST.

**Страницы — по курсору**, от новых к старым. Курсор непрозрачен, его нельзя собрать самому;
смещения и общего числа строк нет. Размер страницы — от 1 до 1000.

`TaskQuery` фильтрует по уровню (обязательно), типу, статусам, родителю, делу и полям нагрузки.
`CommunicationQuery.all()` — по направлению, системе, статусам, делу и `requestId` — идентификатору
запроса во внешней системе.

Одна сущность — `find(level, id, window)` у задач и `find(id, window)` у коммуникаций. Чем уже
окно вокруг времени создания дела, тем меньше партиций обходит чтение.

## Снимки

`TaskSnapshot` — состояние задачи, группы или подзадачи:

| Поле                                   | Что это                                                                  |
|----------------------------------------|--------------------------------------------------------------------------|
| `level`, `id`, `taskType`              | Уровень, идентификатор, тип                                              |
| `taskId`, `batchId`                    | Родители — у групп и подзадач                                            |
| `executionRef`, `origin`               | Дело и создатель                                                         |
| `status`, `statusDescription`, `phase` | Состояние и причина терминального статуса                                |
| `priority`, `createdAt`, `updatedAt`   |                                                                          |
| `payload`                              | Нагрузка сырым JSON                                                      |
| `orphan`                               | Тип без процессора: работа стоит и не поедет, пока процессор не вернётся |

`attempts(snapshot)` — история попыток: фаза, исход и его причина, начало и конец, экземпляр,
число продлений аренды, результат. По ним видно, сколько было заходов, чем кончился каждый
и на каком экземпляре.

`CommunicationSnapshot` — то же для коммуникации, плюс направление, внешняя система и форма
транспорта. Её `attempts(snapshot)` несёт **весь обмен** каждой попытки: запрос и ответ
с заголовками, телами, идентификаторами, временем и статусом, доменную форму ответа и колбэка.

## Поиск по нагрузке

```java
taskInspection.list(
        TaskQuery.of(TaskSnapshot.Level.UNIT).withField("order_id", "A-1024"),
        HistoryWindow.between(from, to),
        PageRequest.first(50));
```

Искать можно только по полям, которые процессоры объявили — см.
[Задачи](../tasks/search-fields.md). Тип задачи указывать не обязательно: поиск идёт во всех типах,
объявивших поле, — так находится всё, что делалось с заказом A-1024, независимо от операции.
Несколько полей сужают поиск до типов, объявивших все.

Поле не объявлено никем — `UnknownSearchFieldException` со списком известных полей
(`knownFields()`). Список полей с подписями и описаниями для формы поиска —
`taskInspection.searchableFields()`.

**У коммуникаций поиска по нагрузке нет.** Найти коммуникацию можно по `requestId` —
идентификатору запроса во внешней системе — и фильтром по системе, направлению, статусам и делу.
Найти коммуникации по параметру запроса без дела пока нельзя: нужен номер заказа — ищите задачи
по полю нагрузки и открывайте их дело, где лежат и коммуникации.

## Сводки

- `taskInspection.summary(window)` — сколько задач, групп и подзадач какого типа в каком статусе,
  с признаком осиротевшего типа. На ней проверяют, что старый тип доработал свои задачи, перед
  тем как его забыть.
- `communicationInspection.summary(window)` — то же по направлениям и системам.
- `communicationInspection.circuitBreakers()` — состояние размыкателей **этого** экземпляра,
  с его именем: число вызовов в окне, доля отказов, время следующей пробы.
- `communicationInspection.correlationKeys(execution)` — ключи корреляции дела.

## Отмена и перезапуск по снимку

Экраны работают со снимками, поэтому у отмены и перезапуска есть перегрузки по ним:

```java
taskInspection.find(TaskSnapshot.Level.UNIT, id, window)
        .map(taskService::restart)
        .ifPresent(result -> log.info("перезапуск: {} — {}", result.accepted(), result.reason()));
```

`TaskService.cancel(TaskSnapshot)`, `restart(TaskSnapshot)` и те же у `CommunicationService`
по `CommunicationSnapshot`. Правила — в [Задачах](../tasks/cancel-restart.md)
и [Коммуникациях](../communications/cancel-restart.md).
