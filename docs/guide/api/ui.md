# Веб-интерфейс

Экраны сопровождения поверх [REST API](rest.md): что стоит в очереди и что упало, карточки задач
и коммуникаций с историей попыток, дело целиком — кто кого создал, — отмена, перезапуск и создание.
Интерфейс — отдельный модуль `taskcomm-ui`, в стартер он не входит: подключают его те, кому он нужен.
Модуль появился в выпуске 2.1.0.

## Подключение

```groovy
implementation platform('xyz.avasilev:taskcomm-bom:2.1.1')
implementation 'xyz.avasilev:taskcomm-spring-boot-starter'
implementation 'xyz.avasilev:taskcomm-ui'
```

```yaml
taskcomm:
  rest:
    enabled: true        # без REST интерфейса нет
```

Интерфейс откроется по `/tc`, REST — по `/tc/api`. Нужно servlet-приложение со Spring MVC, как
и для REST. Модуль не везёт ничего, кроме собранной статики и одного контроллера: Node, React
и прочее остаются в сборке taskcomm, в вашем classpath их нет.

## Настройки

| Свойство                    | По умолчанию | Что делает                                                       |
|-----------------------------|--------------|------------------------------------------------------------------|
| `taskcomm.ui.enabled`       | `true`       | `false` — интерфейса нет, REST работает                          |
| `taskcomm.ui.base-path`     | `/tc`        | путь интерфейса; не корень приложения и не путь REST             |
| `taskcomm.ui.title`         | `taskcomm`   | надпись в шапке и название вкладки — например, имя приложения     |
| `taskcomm.rest.base-path`   | `/tc/api`    | путь REST; интерфейс берёт его отсюда сам                        |

Выключить интерфейс на отдельных стендах — обычным способом Spring Boot, без пересборки: строкой
`taskcomm.ui.enabled: false` в профиле стенда или переменной окружения `TASKCOMM_UI_ENABLED=false`.

Приложение под context path (`server.servlet.context-path`) работает без настроек: интерфейс
подставляет его и в свой адрес, и в адрес REST.

## Безопасность

Как и REST, интерфейс **не закрыт стартером**. `taskcommRequestMatcher` включает и пути REST,
и пути интерфейса, поэтому одной строки из [REST API](rest.md#безопасность) хватает на оба:

```java
.requestMatchers(taskcomm).hasRole("OPERATOR")
```

Интерфейс ходит в REST из браузера с той же сессией, что и страница, — отдельной авторизации у него
нет. Чтобы делить «смотреть» и «управлять», разрешите `GET` одной роли, а `POST` — другой:
интерфейс покажет отказ как «нет прав», а не как ошибку.

```java
.requestMatchers(HttpMethod.GET, "/tc/**").hasAnyRole("VIEWER", "OPERATOR")
.requestMatchers(taskcomm).hasRole("OPERATOR")
```

**CSRF.** Изменяющие запросы интерфейс шлёт с заголовком `X-XSRF-TOKEN`, взятым из cookie
`XSRF-TOKEN`. С включённым CSRF Spring Security отдайте токен в cookie:

```java
.csrf(csrf -> csrf.csrfTokenRepository(CookieCsrfTokenRepository.withHttpOnlyFalse()))
```

Иначе отмена, перезапуск и создание получат `403`, а чтение будет работать.

**Создание из интерфейса — настоящая работа.** Форма ставит задачу или отправляет коммуникацию
во внешнюю систему тем же путём, что и `POST` REST. Кому нельзя отправлять, тому закрывайте `POST`.

## Экраны

Типы задач и внешние системы подписаны названиями из процессоров — `title()`, ключ и описание
`description()` видны в подсказке, на карточке — рядом с заголовком. Без своего названия виден
ключ. Статусы и фазы тоже подписаны словами на языке интерфейса: «Ждёт детей», «Раскрытие».
Значение, которое стоит в REST, логах и метриках (`AWAITING_CHILDREN`, `EXPAND`), видно
в подсказке, а фильтры и ссылки по-прежнему передают его.

- **Обзор** — сколько задач каждого типа и коммуникаций каждой системы в каком статусе, в окне
  чтения истории. Щелчок по статусу ведёт в список с этим фильтром. Тип или система без процессора
  помечены «Нет процессора» — их никто не захватит
  ([Осиротевшие](../operations/orphans.md)). Ниже — размыкатели экземпляра, который ответил.
- **Задачи** — список по уровню, типу, статусам и окну; поиск по полям нагрузки, которые объявили
  процессоры, с их подписями и описаниями. С выбранным типом в списке только его поля; без типа поля
  разложены по типам, а поле, объявленное у нескольких типов, стоит один раз в группе общих — поиск
  по нему идёт во всех этих типах. С выбранным типом у таблицы появляются колонки его полей поиска
  со значениями из нагрузки, так же — у детей на карточке и у подзадач на экране дела. Колонки — все
  поля из реестра, как у поиска, в том числе убранные из кода; поле, у которого менялся путь, —
  одна колонка с первым непустым значением. Сортировка по такой колонке — по загруженным строкам. Карточка — нагрузка, причина статуса, поллер типа, результат последней
  попытки с её фазой и статусом, попытки, отмена и перезапуск. Попытка выбирается щелчком по строке,
  сначала выбрана последняя; под таблицей — её статус и причина целиком, у раскрытия — порождённые
  ею дети страницами (у задачи с группами — группы и подзадачи этих групп, на вкладках — их число),
  у обработки и сборки — результат. В таблице причина — одной строкой, целиком — в подсказке.
- **Коммуникации** — список по направлению, системе, статусам и окну, поиск по идентификатору
  запроса и по ключам. Карточка — идентификаторы запроса и ответа и поллер системы в шапке; ключи
  дедупликации и корреляции, каждый — ссылка на поиск по нему; блок «Обмен» по фазам: обработка
  и асинхронный ответ, у каждой последняя попытка. Стороны подписаны по направлению: что ушло
  в систему и что она ответила, что пришло от системы и что ответили отправителю, колбэк. У каждой —
  идентификатор, время, статус ответа, заголовки и тело как есть; ниже — доменные формы
  ответа и колбэка. Всё, что процессор не записал, так и подписано: «не записано». Под таблицей
  попыток — статус, причина целиком и обмен выбранной попытки в том же виде; сначала выбрана
  последняя.
- **Дело** — дерево «кто кого создал»: задачи, группы и коммуникации, у задачи и группы — полоса
  подзадач по статусам, сами подзадачи — по кнопке, страницами. Рядом — всё дело в порядке
  создания и ключи корреляции.
- **Создание** — в боковой панели поверх текущего экрана; ссылка «Создать», открытая в новой
  вкладке, ведёт на отдельную страницу. Задача по типу, исходящая коммуникация по системе и — если
  включён `taskcomm.rest.manual-inbound` — входящая от системы, чтобы запустить процесс руками.
  Нагрузка — в редакторе JSON; приоритет пустой — значит по умолчанию, и подсказка показывает число
  для выбранного типа; «не раньше» — местное время или ISO-8601 с зоной; дело — идентификатором.
  Кнопка «Создать в этом деле» на экране дела и на карточках открывает форму с уже заданным делом.
  Заполненное сохраняется черновиком: закрыли панель или перезагрузили страницу — поля на месте,
  у каждой вкладки формы свой черновик, у каждой вкладки браузера — свой. После создания черновик
  остаётся, чтобы поставить похожее ещё раз; сбрасывает его кнопка «Очистить».

Таблицы сортируются щелчком по заголовку столбца — то, что уже загружено на экран.

Открывается интерфейс на списке задач. Щелчок по строке списка задач или коммуникаций открывает
карточку в боковой панели; из панели её можно открыть страницей. Выпадающие фильтры подписаны
всплывающей подсказкой, окно — префиксом.

Открытый экран обновляется сам; период — в шапке справа: вручную, 5, 10, 30 или 60 секунд,
по умолчанию 10, выбор помнится в браузере. «Вручную» — только по кнопке «Обновить сейчас», без
загрузки при возврате на вкладку. Фоновая вкладка запросов не шлёт. Боковые панели тянутся за край,
ширина помнится. В подвале справа —
экземпляр, который ответил (то же имя, что в попытках: через него идут запросы этой вкладки, его же
размыкатели на обзоре), версия стартера, тема — тёмная по умолчанию — и язык: русский или английский,
по браузеру. Выбор темы и языка помнится в браузере.

**Окно.** Списки и сводки ищут в окне по времени создания **дела**, по умолчанию —
`taskcomm.rest.search-window`. Выбор окна есть на каждом экране, а над списком написано, где искали:
«не нашлось» в окне и «нет вовсе» — разные ответы ([Поиск и окно](rest.md#поиск-и-окно)).

**Большое дело.** Экран дела не читает подзадачи целиком: дерево строится из задач, групп
и коммуникаций, подзадачи — счётчиками. Но счёт подзадач у дела на миллион строк — секунды,
и экран повторяет его с выбранным периодом, пока открыт.
